# 001 — a2ui-nsh core and desktop

## What

Build `a2ui-nsh`, an open-source A2UI 1.0 renderer on Native Shell (`longbridge/nsh`, measured on `0.6.1`), using a zero-dependency pure TypeScript protocol core paired with a thin TSX component layer over `nsh` and `nsh/base`. An agent streams A2UI v1.0 JSON envelopes describing UI structure and data; `a2ui-nsh` validates, resolves bindings, and renders native controls across all eight `nsh` targets (macOS AppKit, iOS UIKit, Android views, Windows Win32/Direct2D, Linux GTK 4, GPUI, ratatui TUI, and Web/WASM) from one codebase. This first slice delivers the v1.0 core passing upstream conformance suites, 15 of the 18 Basic Catalog components with per-component tests, a real ERP-style customer list and edit form running on macOS, a clean multi-catalog extension point for `xlarge`, and a weekly compatibility build against `nsh`'s latest release.

## Why

An agentic ERP needs screens that AI agents can generate safely on demand without shipping arbitrary code on every turn, while still rendering with fast native desktop and mobile controls rather than an embedded browser. Today, existing A2UI renderers either target only the web DOM (`@a2ui/web_core` + Lit/React/Angular), draw custom non-native pixels (Flutter), cover Apple platforms only (SwiftUI), target an outdated pre-1.0 wire format across incompatible desktop-only Rust crates (`liangdi/a2ui`), or are too early to render anything (`oku-theory/a2ui-rs`).

`a2ui-nsh` combines A2UI v1.0's declarative data protocol with `nsh`'s native multi-platform runtime, QuickJS sandbox, and Ed25519-signed `.nshpkg` distribution. Between the agent and the renderer, only A2UI v1.0 JSON envelopes cross (`createSurface`, `updateComponents`, `updateDataModel`, `deleteSurface`, `callRendererFunction`, `agentFunctionResponse` inbound; `action`, `callAgentFunction`, `rendererFunctionResponse`, `error` outbound). Credentials, raw database handles, and signing keys never cross into the renderer.

## Not doing

- Protocol v0.8, v0.9, or v0.9.1 backward compatibility (v1.0 only).
- Agent-side SDKs, prompt generators, or Express DSL compilers (renderer side only).
- The `xlarge` company catalog components themselves (dense grid, charts, ERP form rules) — this spec defines and tests the extension seam; Spec 2 builds the `xlarge` catalog.
- Mobile packaging, Flutter side-by-side benchmarks, or desktop engine comparisons (Spec 3).
- Remaining 3 Basic Catalog components (`Slider`, `Video`, `AudioPlayer`) — deferred to the immediate follow-up slice to finish 18/18 after the ERP slice ships.
- Implementing the Layer-2 signing/approval backend service — this spec enforces the renderer-side capability sandbox and catalog boundary; operational signing workflows use `nsh`'s existing CLI (`keygen`, `certify`, `publish`, `verify`, `revoke`).

## 2. Design and where `a2ui-nsh` is better

### Core advantages over every reference

1. **Full A2UI v1.0 conformance with automated upstream tracking.** Like `oku-theory-a2ui-rs`, we run `google-A2UI`'s language-agnostic YAML suites directly (`conformance/core/*.yaml`, `conformance/e2e/*.yaml`) and emit executed-case manifests (`conformance/manifest_corpora.json`) with a strict skip list that fails CI if a skip goes stale. Unlike `liangdi-a2ui`, we strictly follow v1.0 (`"version": "1.0"`, `@path`, `@call`, `@catalogId`, `@accessibility`, `@metadata`, `@checks`, `@index`, `callRendererFunction`, `callAgentFunction`, `rendererFunctionResponse`, `agentFunctionResponse`).
2. **All 18 Basic Catalog components + 14 functions on one native renderer.** Every component maps to `nsh` primitives (`View`, `Text`, `Image`, `Scroll`, `List`, `Canvas`, `Video`, `AudioPlayer`) and `nsh/base` accessible controls (`Button`, `Input`, `Checkbox`, `RadioGroup`, `Select`, `Combobox`, `Slider`, `DatePicker`, `TimeField`, `Tabs`, `Dialog`, `TextView`).
   - Slice 1 (this spec) ships **15 components**: `Text`, `Image`, `Icon`, `Row`, `Column`, `List`, `Card`, `Tabs`, `Modal`, `Divider`, `Button`, `TextField`, `CheckBox`, `ChoicePicker`, `DateTimeInput`.
   - Slice 1b (follow-up) completes the remaining **3**: `Slider` (`nsh/base` `Slider`), `Video` (`nsh` `Video` + poster `<Image>` overlay until `onLoad`), and `AudioPlayer` (custom control bar over `nsh` `AudioPlayer`).
   - `Icon` maps all 59 Basic Catalog icon names to bundled 24×24 SVG path data and renders both named icons and dynamic `svgPath` strings natively via `nsh`'s `Path2D` + `<Canvas>` (`nsh-llms-full.txt:19940-19976`).
   - `Text` supports plain text via `<Text>` and A2UI's simple Markdown subset via `nsh/base` `<TextView>` (with HTML/image/link disabling to match `adapter/markdown_subset.yaml`).
3. **Fine-grained native reactivity, two-way bindings, actions, and streaming.** A2UI surfaces store per-surface reactive signals (`components` and per-path reactive `DataModel` reads) backed by `nsh`'s native Rust reactive graph (`nsh-llms-full.txt:12354`). Scalar `updateDataModel` writes update only subscribed leaf bindings with zero parent remounts (proven in `spike/App.test.tsx`). Incremental streams support out-of-order components via non-crashing pending placeholders, type-change identity resets, cycle/unknown-type diagnostics (`UNKNOWN_COMPONENT_TYPE`, `CYCLIC_REFERENCE`), and full subscription cleanup on `deleteSurface`. Actions evaluate `context` and `userMessage` at dispatch time, enforce `allowedCallers` and `requiresUserActivation` on local and agent-routed function calls, and serialize strict v1.0 outbound envelopes.
4. **Native accessibility across platforms.** Every component plumbs `@accessibility.{label,description,live,hidden}` onto `nsh`'s native views, which map to VoiceOver (AppKit/UIKit), TalkBack (Android), UI Automation (Win32), AT-SPI (GTK 4), AccessKit (GPUI), and ARIA (Web). Explicit `@accessibility.label` overrides inferred text labels. For the two `nsh 0.6.1` accessibility gaps measured in the spike (`ComponentHostProps` missing `accessibilityDescription`/`accessibilityElementsHidden`, and `accessibilityLiveRegion` being Android-only in TSX), we apply a thin `<View>` wrapper for `description`/`hidden` and pair `role="alert"` / `announce()` for live regions while tracking upstream `nsh` fixes.
5. **One renderer for all eight `nsh` targets.** A single TSX renderer runs on macOS (AppKit), iOS (UIKit), Android views, Windows (Win32/Direct2D), Linux (GTK 4), GPUI, terminal (ratatui TUI), and Web (HTML/CSS/WASM) with no per-platform widget rewrites and no Cargo dependency conflicts. Layouts are designed phone-width first (`390 px`) and desktop (`1280 px`), adapting cleanly via `platform.desktop` / responsive sizing (Design Rule 15).
6. **Multi-catalog extension point for `xlarge`.** A `CatalogRegistry` maps `catalogId -> { schema, components, functions }` following v1.0's strict resolution order (explicit component `@catalogId` / function `catalogId` → surface default `catalogId` → error, zero implicit fallback). Company catalogs like `xlarge` register custom components (dense virtualized `List`, `DataTable` grid, `Plot` charts, ERP form validation rules) and domain functions alongside the Basic Catalog on the same surface, sharing the JSON catalog schema across Solid, Flutter, and `nsh`.
7. **Two-layer safety architecture (data by default, signed sandbox for new code).**
   - **Layer 1 (default, ~95% of ERP screens):** Agents emit A2UI JSON referencing pre-registered catalog components only. No agent-authored code executes. Malformed or hostile payloads fail closed against strict schema, topology, cycle, depth, and regex limits.
   - **Layer 2 (catalog growth):** When a screen genuinely needs a component absent from the catalog, a model proposes a TSX module that cannot run directly. It must pass:
     1. Automated checks: `nsh check` (TypeScript 7 type check) and `nsh test` (headless behavior + capability tests).
     2. Human review: a maintainer inspects the code and rendered output and explicitly approves.
     3. Company signing: a human-controlled release key certified by an offline root signs the package (`nsh keygen`, `nsh certify`, `nsh publish` → `.nshpkg`). The model never holds any signing key.
     4. Capability-free sandbox: approved components run inside `nsh`'s hardened QuickJS VM (`eval` and `Function` disabled, frozen prototypes) with minimal capabilities (`"capabilities": { "host": ["a2ui.*"] }` — zero `network`, `fs`, `process`, `webview`, `clipboard`, `openUrl` unless explicitly granted by the host) and strict VM limits (`256 MB` heap, `2 s` per-call CPU budget, `200,000` nodes; `nsh-llms-full.txt:8381-8390`). The component receives data only via props / A2UI data model and communicates outward only via A2UI actions.
     5. Catalog promotion & revocation: once promoted, all subsequent screens invoke the component purely as Layer-1 data. Faulty or compromised packages are withdrawn via `nsh revoke`.
   - **Server as final authority:** Regardless of what any client screen renders, the backend re-verifies user permissions and business invariants on every action. Client safety prevents code execution, data exfiltration, and UI DoS; human approval + visual tests mitigate deceptive UI.

### Adherence to design principles (`.agents/skills/design/SKILL.md`)

- **Boundaries & Pure Core (Rules 1–3):** `src/core/` is pure TypeScript with zero `nsh` or I/O imports; `src/store/` binds it to `nsh` `signal()`s; `src/catalog/` and `src/renderer/` are thin TSX shells. Transport, clock (`nowIso`), and URL opening enter through narrow injected seams.
- **Types & Errors (Rules 4, 7):** Incoming JSON is parsed and validated once at the `MessageProcessor` edge into discriminated unions; inner code never handles raw untyped strings. Errors are typed with A2UI error codes (`VALIDATION_FAILED`, `INTEGRITY_ERROR`, `CATALOG_NOT_FOUND`, `EXPRESSION_ERROR`, `EXECUTION_ERROR`, `INVALID_FUNCTION_CALL`, `UNKNOWN_COMPONENT_TYPE`, `CYCLIC_REFERENCE`) and never leak secrets or stack traces. Fail closed on invalid capabilities, disallowed callers, or unactivated gestures.
- **Limits & Guards (Rule 10):** Explicit named caps on nesting depth, JSON Pointer array indices, expression length/depth, pending RPC count, and regex pattern length (256 code points + safe-pattern check rejecting lookbehinds/backreferences/nested quantifiers per Basic Catalog `regex` dialect in `catalogs/basic/v1/catalog.json:721`), with overrides only through typed processor config for tests.
- **Dependencies & Tests (Rules 12, 16):** Zero runtime npm dependencies in `src/core/` and `src/renderer/`; dev/conformance harness uses only `nsh` (and a lightweight YAML runner script for upstream suites). Every acceptance line and every component has behavior-level tests.

## 3. Core choice and spike findings

### Options evaluated

1. **Wrap `liangdi-a2ui`'s `a2ui-base` via `nsh` `#[native_module]`:** **Rejected.** Implements an outdated pre-1.0 wire dialect (`path`/`call`, `callFunction`, `actionResponse`, missing `@accessibility.{live,hidden}`), runs zero upstream conformance suites, and requires rewriting the protocol layer anyway.
2. **Wrap `oku-theory-a2ui-rs`'s `a2ui-runtime` via `nsh` `#[native_module]`:** **Rejected for Slice 1 (kept as future seam).** While `a2ui-runtime` 0.3.0 is cleanly engineered and v1.0-faithful, it currently passes only stages C1–C2 and skips 13 conformance actions (`crates/a2ui-conformance/skips.toml:2-15`: no `MessageProcessor`, validator, functions, actions, RPC, or node resolver yet). More fundamentally, adding **any** Rust crate (`"rust"` in `nsh.json`) imposes four architectural costs measured directly in `nsh 0.6.1`:
   - **Breaks `.nshpkg` OTA delivery:** `nsh` signed packages carry TSX only; Rust crate changes require full native app rebuilds and store releases (`target/refs/nsh-llms-full.txt:7411-7414, 7961-7965`).
   - **Breaks stock host embedding:** Any host embedding `NativeShell.xcframework`, `nsh.aar`, GPUI `AppView`, or stock `nsh run` can load a pure TSX bundle/.nshpkg directly; a `#[native_module]` forces every host binary across all 8 platforms to recompile and link our Rust crate (including Android NDK, Xcode, and `wasm32` + `clang` + `wasm-bindgen-cli` for web, `nsh-llms-full.txt:1569, 4779-4790`).
   - **Weakens the sandbox boundary:** Rust crates compile into the host binary and bypass QuickJS heap/CPU/node limits (`nsh-llms-full.txt:8356, 8782-8784`), whereas a TypeScript core inside QuickJS gets 256 MB heap, 2 s per-call CPU interruption, and 200k node caps automatically against hostile LLM payloads.
   - **Redundant reactive layer:** `nsh`'s `signal()` / `computed()` / `<Each>` / `<If>` reactive graph is *already* native Rust (`nsh-llms-full.txt:12354`). Bridging `DataModel` reads across QuickJS↔Rust FFI as JSON adds marshaling overhead where TSX reading `nsh` signals stays direct.
3. **Write our own pure TypeScript v1.0 core inside `nsh`:** **Chosen.**

### Evidence from the throwaway spike (`spike/`)

We built a throwaway `nsh 0.6.1` TSX app in `spike/` (`spike/a2ui.ts`, `spike/App.tsx`, `spike/samples.ts`, `spike/App.test.tsx`, `spike/nsh.json`) rendering `Text`, `Button`, `Row`, and `Column` from two verbatim `google-A2UI` v1.0 payloads:
- `conformance/core/adapter_conformance.yaml` (`action_execution_event_vs_local_function_call`, lines 323–357): inline `createSurface` with `dataModel`, `Row`, `Button`, `Text`, absolute `@path` action context (`"/itemId"` → `"sku-42"`), `buy_item` event, and local `incrementCounter` functionCall.
- `catalogs/basic/v1/examples/scaffold-incremental.json` (lines 5–133): `createSurface`, incremental `updateDataModel` + `updateComponents`, template-bound `Column` over `/restaurants`, relative `@path` bindings (`title`, `subtitle`, `address`), and template-scoped `book_now` action.

**Measured results on `nsh 0.6.1 (2f51d86)`:**
- **Effort & size:** `393` lines for the pure TS core (`spike/a2ui.ts`) + `460` lines for the TSX renderer (`spike/App.tsx`). Release build (`nsh build spike/App.tsx --release`): **11.0 KB JS, 12.6 KB QuickJS bytecode in 31 ms** (zero Cargo build, zero Node needed).
- **Type checking & headless tests:** `nsh check spike` passed with TypeScript 7 (`tsgo`) offline in `< 1 s`. `nsh test spike` ran **4 tests (4 passed, 0 failed) in 1.1 s** inside the hardened QuickJS + native Taffy engine.
- **Reactivity fit:** Separating per-surface `components` and `dataModel` signals on `nsh`'s Rust reactive graph gave **0 node remounts** when `updateDataModel` mutated `/restaurants/0/title` (`"The Golden Fork"` → `"The Platinum Fork"`), verified via a mount counter probe, while the subsequent `Book now` press resolved `"The Platinum Fork"` at dispatch time.
- **Sandbox fit:** Declaring `"capabilities": { "host": ["a2ui.*"] }` in `spike/nsh.json` restricted the renderer exclusively to the A2UI host bridge channel while `app.host.send` and `app.host.posts()` cleanly tested inbound messages and outbound v1.0 action envelopes.

**Concrete `nsh 0.6.1` gaps discovered during the spike:**
1. **`nsh/base` `ComponentHostProps` drops several accessibility props:** `spike/.nsh/types/nsh/types.d.ts:188` excludes `accessibilityDescription`, `accessibilityElementsHidden`, `importantForAccessibility`, `accessibilityHint`, and `accessibilityState` from `nsh/base` components like `<Button>`, whereas primitive `<View>` and `<Text>` accept them. *Workaround:* wrap `nsh/base` controls in a transparent `<View>` when `@accessibility.description` or `hidden` is set; file upstream issue/PR on `longbridge/nsh`.
2. **`accessibilityLiveRegion` is Android-only in TSX:** `target/refs/longbridge-nsh/crates/nsh-core/src/props.rs:395` defines `#[prop(android = "accessibilityLiveRegion")]`, so TSX cannot set `live: "polite" | "assertive"` cross-platform even though macOS, Linux, Windows, and Web backends already implement `live_region` in Rust. *Workaround:* emit `role="alert"` for `assertive` + `announce()` on dynamic changes for `polite`/`assertive`, and request a cross-platform `accessibilityLiveRegion` prop upstream.
3. **`nsh/test` omits accessibility-tree & layout introspection APIs present in Rust:** `spike/.nsh/types/nsh/test.d.ts:379-501` supports `label:`, `role:`, `id:`, `text:` selectors, `enabled()`, and `value()`, but does not expose `accessibilityDescription()`, `accessibilityState()`, `accessibilityLevel()`, or `layoutNodes()` (all of which exist on Rust `nsh_testing::Screen` in `crates/nsh-testing/src/screen.rs:1224,2245-2273`). *Workaround:* run core conformance directly against `src/core/`, and verify full accessibility metadata in adapter tests via a typed test-mode attribute mirror alongside `nsh/test` selector assertions.
4. **Missing QuickJS `Intl` features:** `nsh` QuickJS omits `Intl.PluralRules` and lacks month/weekday names for several non-English locales (e.g., Turkish, Russian) and an IANA timezone database (`target/refs/nsh-llms-full.txt:51671-51673`). *Mitigation:* ship a small, deterministic CLDR plural-rule table for `pluralize` and our own Unicode TR35 formatter for `formatDate` in `src/core/functions/`.
5. **Startup capability warning:** With strict `"capabilities": { "host": ["a2ui.*"] }`, `nsh 0.6.1` logs `warn the status bar is not granted: add "statusBar": true to capabilities in nsh.json` during boot even when the app never touches `statusBar`. Harmless, but worth reporting to `longbridge/nsh`.
6. **Media/icon composition needs thin wrappers:** `<Video>` lacks `posterUrl` (and GPUI video is Linux-only, `nsh-llms-full.txt:4687, 27610`), `AudioPlayer` is an imperative class without UI chrome (`45830`), and `Icon` requires a 59-icon SVG path table (plus a fallback path) rendered via `Path2D`/`<Canvas>` matching upstream `catalogs/basic/v1/catalog.json` (lines 76–134).
7. **`TextView` Markdown subset disabling & `nsh/test` `host.available()` (measured in T9 on `nsh 0.6.1`):** `TextView.parse(md, { html: false, math: false, alerts: false })` disables HTML natively, but `MarkdownOptions` has no toggle to disable Markdown links or images; `src/catalog/basic/markdown.ts` strips `link` and `image` nodes from the parsed `TextViewDocument` AST before rendering `<TextView document={...} />`, wrapped in `<View>` for full accessibility props (Gap #1). Separately, in `nsh 0.6.1` (`crates/nsh-testing/src/module.rs:754`), `open(entry, { host: { params } })` without `handlers` populates `host.params` while `host.available()` returns `false`, so test harnesses must read `host.params` directly rather than gating on `host.available()`.
8. **`List` horizontal cross-axis sizing/alignment, non-bubbling `onPress` on `Modal` triggers, and `nsh/test` backdrop hit-testing (measured in T10 on `nsh 0.6.1`):** (a) `nsh` `<List>` cells are independent Taffy roots (`crates/nsh-core/src/core/list.rs:42`), so `<List horizontal>` cannot derive its height from children without an explicit fixed `height` (which A2UI `List` does not declare), and `ListContentStyle` (`types.d.ts:788`) supports only padding/gaps without `alignItems`; vertical A2UI `List` uses virtualized `<List viewport="parent">` with a per-cell alignment `<View>`, while `direction: "horizontal"` uses `<Scroll horizontal>`. (b) `nsh` routes `onPress` strictly to the innermost pressable view (`website/docs/touch-and-gestures.md:83`), so a wrapper `<View onPress>` around a pressable `Modal.trigger` (e.g. `Button`) never fires; `BasicModal` exposes `ModalTriggerContext` (cleared inside `content`) for pressable triggers alongside the wrapper `onPress` for non-pressable triggers. (c) `nsh/test` `app.press(selector)` targets only the geometric center of a view with no offset option, so pressing a full-screen `<Dialog>` `backdropTestID` behind a centered popup rejects with `ERR_NSH_TEST_COVERED`; headless tests verify backdrop presence, Close button, `Escape`, and `app.back()` dismissal.
9. **`DatePicker` / `TimeField` ISO 8601 parsing & missing time bounds, and `AccessibilityRole` omitting `"textbox"` (measured in T11 on `nsh 0.6.1`):** (a) `nsh/base` `TimeField` (`crates/nsh-base/src/time_field.rs`) has no `min`/`max` props, so `BasicDateTimeInput` enforces date bounds via `DatePicker.disabledMatcher` (`{ before, after }`) and enforces time bounds by clamping `onChange` values in `src/catalog/basic/datetime_helpers.ts`. (b) Both `DatePicker` (`crates/nsh-base/src/date_picker.rs:138-158`) and `TimeField` (`crates/nsh-base/src/time_field.rs:104-131`) reject empty strings `""` and timezone suffixes (`Z`, `+HH:MM`) in `JsValue::from_js`, so `datetime_helpers.ts` validates and normalizes incoming A2UI ISO 8601 strings to `null` / `YYYY-MM-DD` / `HH:MM` before passing them to `nsh/base`. (c) `nsh 0.6.1` `AccessibilityRole` (`types.d.ts:725`) omits `"textbox"`, so `BasicTextField` leaves `role` unset on `<Input>` to let the native text input report its platform role.
10. **`nsh.json` `"window"` settings require `"application": true` under strict capabilities (measured in T13 on `nsh 0.6.1`):** Declaring `"window": { "title", "defaultSize", "minSize" }` in `nsh.json` emits a `Command::Desktop` against `ROOT_ID` (`crates/nsh-core/src/core/mod.rs:3866-3876`) that `Access::allows_application()` denies with `warn the application (...) is not granted: add "application": true to capabilities in nsh.json` unless `"application": true` is granted (which also exposes menu bar, tray, global shortcuts, and quitting). `examples/erp-customers/nsh.json` keeps strict `"capabilities": { "host": ["a2ui.*"] }` rather than widening privilege.

**Reversibility:** `AGENTS.md` §0 originally assumed a Rust native module for the protocol core. Because `src/core/` sits behind a narrow `MessageProcessor` interface, we can still swap in a Rust core (`oku-theory-a2ui-rs` once Plans 3–5 land, or our own crate) for a pure-Rust `"root"` host later without rewriting a single catalog component.

## Risks

- **`nsh` pre-1.0 API churn (`0.6.1` → `0.7.x`):** `nsh` moves fast and may rename `nsh/base` props or `nsh.json` keys. *Mitigation:* pin `nsh` version in `docs/upstream.toml`, isolate all `nsh` UI bindings inside `src/catalog/` and `src/store/`, and run the weekly latest-release CI workflow.
- **ReDoS in QuickJS `RegExp` for `regex` function:** QuickJS uses a backtracking regex engine, unlike Rust's linear-time `regex` crate. *Mitigation:* implement a strict static pattern validator for the A2UI portable regex dialect (`catalogs/basic/v1/catalog.json:721`: reject >256 code points, backreferences, lookbehinds, named groups, `\p{...}`, and nested quantifiers) before compiling any `RegExp`, backed by QuickJS's 2 s per-call CPU budget.
- **Accessibility & test-introspection gaps in `nsh 0.6.1`:** `ComponentHostProps` omits `accessibilityDescription`/`accessibilityElementsHidden`, `accessibilityLiveRegion` is Android-only in TSX, and `nsh/test` lacks `accessibilityDescription()` / `layoutNodes()`. *Mitigation:* use `<View>` wrappers and `role="alert"`/`announce()` workarounds today, and track upstream `longbridge/nsh` PRs/issues.
- **Large ERP lists inside QuickJS:** Very large unvirtualized lists or deep JSON cloning on every `updateDataModel` could hit frame budgets. *Mitigation:* map A2UI `List` directly to `nsh`'s virtualized `<List>`, use structural sharing (path-copied updates, not full `JSON.parse(JSON.stringify(...))` from the spike) in `src/core/data_model.ts`, and gate on `core/message_processor_scaling.yaml`.
- **Deceptive UI in Layer-2 TSX components:** A sandboxed component cannot exfiltrate data or bypass server authorization, but could mislead a human (wrong label, hidden button). *Mitigation:* mandatory human code + visual review before signing, capability-free defaults, and rapid withdrawal via `nsh revoke`.

## Questions

Answered 2026-11-20: the owner approved the spec with each recommendation as written (pure TypeScript core with a seam for a later Rust core; Apache-2.0; the 15-component Slice 1; macOS first, then web and TUI).

1. **Core language switch vs `AGENTS.md` §0:** Recommend building the A2UI v1.0 core in **pure TypeScript inside `nsh`** (keeping a narrow interface seam for a future Rust core) instead of a Rust `#[native_module]`, and updating `AGENTS.md` §0 once approved. *Why it matters:* this preserves stock multi-platform builds across all 8 `nsh` targets, keeps `.nshpkg` OTA updates working, and confines the entire parser/evaluator inside QuickJS's sandbox.
2. **Repository license before going public:** Recommend **Apache-2.0** (matching both `google-A2UI` and `longbridge/nsh`) instead of the template's default `MIT`, so embedding upstream A2UI v1.0 catalog schemas carries no mixed-license friction. *Why it matters:* once public, changing a license across contributors is hard.
3. **Slice 1's 15-component cut:** Recommend shipping `Text`, `Image`, `Icon`, `Row`, `Column`, `List`, `Card`, `Tabs`, `Modal`, `Divider`, `Button`, `TextField`, `CheckBox`, `ChoicePicker`, and `DateTimeInput` in Slice 1, leaving `Slider`, `Video`, and `AudioPlayer` for Slice 1b. *Why it matters:* this covers every control needed by an ERP list + form screen on day one without delaying the first working macOS demo on media player chrome.
4. **Target order for manual visual walks:** Recommend verifying **macOS (AppKit)** first in Slice 1, followed by **Web** and **TUI** smoke checks before moving to iOS/Android in Spec 3. *Why it matters:* all three run locally on this Mac with zero mobile device/store setup.
